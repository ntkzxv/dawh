# Requirements สำหรับออกแบบ UX/UI — Sales และ Accounts Receivable (A/R)

วันที่: 4 พฤศจิกายน 2026

วัตถุประสงค์: สรุปขอบเขต เมนู หน้าจอ ข้อมูล และขั้นตอนใช้งาน เพื่อส่งต่อให้ออกแบบ UX/UI

เอกสารนี้แยกข้อกำหนดที่ยืนยันแล้วออกจากข้อเสนอการจัดหน้าจอและเรื่องที่รอกำหนด ไม่ใช่ specification สำหรับเขียน logic ทางการเงินหรือฐานข้อมูล

## 1. ภาพรวมและขอบเขตโมดูล

| โมดูล | หน้าที่ |
| --- | --- |
| **Sales — การขาย** | จุดทำรายการของพนักงาน: จัดการข้อมูลลูกค้า บันทึกขายสด/ผ่อน เปิดสัญญาผ่อนอัตโนมัติ บันทึกชำระค่างวด และออกเอกสาร |
| **Accounts Receivable (A/R) — ข้อมูลลูกค้าและลูกหนี้การค้า** | ศูนย์ดูข้อมูลรายละเอียดลูกค้า ประวัติซื้อ สัญญา การชำระเงิน ยอดคงค้าง และประวัติติดตามหนี้ ซึ่งเชื่อมจากรายการใน Sales |

- A/R ใช้แสดงข้อมูล ไม่ใช่จุดสร้างหรือแก้ไขรายการธุรกิจ
- การบันทึกใน Sales ต้องทำให้ข้อมูลที่เกี่ยวข้องแสดงใน A/R อัตโนมัติ ไม่ต้องกรอกซ้ำ
- ลูกค้าซื้อสดและซื้อผ่อนใช้ทะเบียนและโปรไฟล์ลูกค้าชุดเดียวกัน ลูกค้าคนเดียวซื้อได้ทั้งสองแบบ
- A/R แสดงข้อมูลลูกค้าซื้อสดได้ แต่ยอดซื้อสดที่ชำระครบไม่ถูกนับเป็นหนี้ค้างชำระ
- ระบบเก็บข้อมูลการชำระเงินที่พนักงานบันทึก ไม่ได้ประมวลผลการจ่ายเงินจริง

## 2. ข้อกำหนดการขายและสัญญาที่ตกลงแล้ว

### 2.1 บิลและสินค้า

- แยกบิลซื้อสดกับบิลซื้อผ่อน ห้ามรวมสองประเภทไว้ในบิลเดียว
- ลูกค้าที่ซื้อทั้งสดและผ่อนในครั้งเดียว ให้สร้างคนละบิลโดยเชื่อมกับลูกค้าคนเดียวกัน
- หนึ่งบิลมีสินค้าได้หลายรายการ
- บิลผ่อนใช้เงื่อนไขเดียวกันทั้งบิล และสร้างสัญญากับตารางผ่อนหนึ่งชุดต่อบิล
- ยังไม่รองรับเงื่อนไขผ่อนต่างกันรายสินค้าภายในบิลเดียว พนักงานจัดการแยกรายการเอง

### 2.2 เงื่อนไขผ่อน

| รายการ | ข้อกำหนด |
| --- | --- |
| ฐานราคาสินค้า | ยอดรวมราคาสินค้าทุกรายการในบิล |
| เงินดาวน์ | ระบุเป็นจำนวนเงินบาท |
| อัตราดอกเบี้ย | ระบุเป็นเปอร์เซ็นต์รวมทั้งสัญญา |
| ฐานคิดดอกเบี้ย | ราคาสินค้าเต็มทั้งบิล ก่อนหักเงินดาวน์ |
| จำนวนงวด | ระบุจำนวนเดือน ผ่อนรายเดือน |
| ค่างวด | ระบบคำนวณจากสูตรด้านล่าง |
| วันครบกำหนดงวดแรก | พนักงานเลือก |
| งวดถัดไป | สร้างเป็นรายเดือน โดยใช้วันที่เดียวกันเป็นแนวทางเบื้องต้น; logic วันที่และกรณีพิเศษรอกำหนดภายหลัง |

```text
ราคาสินค้า = ผลรวมราคาสินค้าทุกรายการในบิล
ดอกเบี้ยรวม = ราคาสินค้า × อัตราดอกเบี้ย ÷ 100
ยอดที่ต้องผ่อน = ราคาสินค้า + ดอกเบี้ยรวม − เงินดาวน์
ค่างวดต่อเดือน = ยอดที่ต้องผ่อน ÷ จำนวนเดือน
```

ตัวอย่าง: ราคาสินค้ารวม 10,000 บาท ดอกเบี้ย 10% ทั้งสัญญา เงินดาวน์ 2,000 บาท ผ่อน 12 เดือน จะได้ดอกเบี้ยรวม 1,000 บาท ยอดที่ต้องผ่อน 9,000 บาท และค่างวด 750 บาทต่อเดือน

สูตรนี้เป็นข้อสรุปจากการสนทนา ส่วนการปัดเศษและความสัมพันธ์ระหว่างราคาสินค้ากับส่วนลด/ภาษียังรอกำหนด

### 2.3 ช่องทางชำระเงินและการบันทึกค่างวด

- ตอนซื้อ ให้เลือกช่องทางชำระเงินได้: **โอน / เงินสด / บัตรเครดิต**
- ประเภทการซื้อ **สด/ผ่อน** เป็นคนละข้อมูลกับช่องทางชำระเงิน
- หลังเปิดสัญญา ให้พนักงานบันทึกการชำระค่างวดใน Sales ไปก่อน
- เมื่อบันทึกการชำระค่างวดแล้ว ข้อมูลประวัติการชำระ สถานะงวด และยอดคงค้างต้องอัปเดตใน A/R
- ช่องข้อมูลและกติกาการบันทึกค่างวดโดยละเอียด รวมถึงช่องทางที่ใช้กับค่างวด รอกำหนดเพิ่มเติม

### 2.4 เอกสาร PDF

- ครอบคลุม **บิลขาย / ใบเสร็จรับเงิน / ใบกำกับภาษี**
- ออกใบเสร็จได้ทั้งการซื้อสด การรับเงินดาวน์ และการรับชำระค่างวดแต่ละครั้ง
- บิลขายต้องแสดงว่าใครซื้ออะไร จำนวนสินค้า ราคาต่อหน่วย ยอดแต่ละรายการ และยอดรวมทั้งบิล
- ข้อมูลประกอบเอกสาร: ข้อมูลร้าน วันที่ เลขที่เอกสาร และช่องทางชำระเงิน
- ใบเสร็จเงินดาวน์/ค่างวดต้องเชื่อมกับบิลขายและสัญญา และแยกยอดรับชำระครั้งนั้นออกจากยอดซื้อทั้งบิล
- รูปแบบเอกสาร ข้อมูลภาษี และกติกาเลขที่เอกสารรอกำหนด ห้ามถือว่าตัวอย่างหน้าจอเป็นข้อสรุปด้านภาษี

## 3. โครงสร้างเมนูเสนอสำหรับออกแบบ UX/UI

โครงสร้างนี้จัดตามหลัก Sales ใช้ทำรายการ และ A/R ใช้ดูข้อมูล การจัดตำแหน่งเมนู/แท็บสามารถปรับในขั้นออกแบบได้โดยรักษาขอบเขตดังกล่าว

### 3.1 Sales

| เมนู | หน้าจอ/งานที่รองรับ |
| --- | --- |
| **รายการขาย** | ดูรายการขาย เปิดรายละเอียดบิล และสร้างรายการขายใหม่ โดยแยกประเภทสด/ผ่อน |
| **ลูกค้า** | ค้นหา เพิ่ม และจัดการข้อมูลลูกค้าชุดเดียวกับที่ A/R ใช้; เข้าถึงได้จากขั้นตอนสร้างรายการขายด้วย |
| **บันทึกชำระค่างวด** | ค้นหาลูกค้า/สัญญา ดูตารางผ่อน และบันทึกข้อมูลการชำระที่เกิดขึ้นแล้ว |

เอกสาร PDF เข้าถึงจากรายละเอียดบิลหรือรายการชำระที่เกี่ยวข้อง ไม่จำเป็นต้องแยกเป็นเมนูหลักในแบบร่างแรก

**ข้อเสนอเพิ่มเติมที่ยังไม่ยืนยัน:** ถ้ามีการกรอกประวัติติดตามหนี้เอง ให้จัดจุดบันทึกไว้ใน Sales ตามหลักการทำรายการทั้งหมดในโมดูลนี้ ส่วน A/R ใช้ดูประวัติ แหล่งที่มาและข้อมูลที่ต้องกรอกยังรอกำหนด

### 3.2 Accounts Receivable (A/R)

| เมนู | หน้าจอ/ข้อมูลที่รองรับ |
| --- | --- |
| **ภาพรวม** | สรุปหนี้คงค้าง สถานะการผ่อน รายการชำระล่าสุด และรายการเกินกำหนด; ขอบเขตตัวเลขภาพรวมรอกำหนด |
| **ทะเบียนลูกค้า** | ลูกค้าทั้งหมด ทั้งซื้อสดและซื้อผ่อน พร้อมเปิดโปรไฟล์รายบุคคล |
| **สัญญาผ่อนชำระ** | รายการสัญญา รายละเอียดเงื่อนไข สินค้า ตารางงวด และยอดคงค้าง |
| **ประวัติการชำระเงิน** | ดูรายการรับชำระจากซื้อสด เงินดาวน์ และค่างวด พร้อมเอกสารที่เกี่ยวข้อง |
| **รายการเกินกำหนด** | ดูลูกค้า/สัญญา/งวดที่ค้างชำระ และเชื่อมไปยังรายละเอียดหรือประวัติติดตามหนี้ |

## 4. หน้าจอหลักใน Sales

### 4.1 รายการขายและรายละเอียดบิล

- รายการขายต้องแยกแยะบิลซื้อสดและซื้อผ่อนได้
- รายละเอียดบิลแสดงลูกค้า รายการสินค้า ราคา ยอดรวม ช่องทางชำระ และเอกสารที่เกี่ยวข้อง
- บิลผ่อนต้องเชื่อมไปยังรายละเอียดสัญญาที่สร้างอัตโนมัติ
- ปุ่มสร้างรายการขายใหม่เป็นจุดเริ่มต้นของ flow ขายสดและขายผ่อน
- ตัวกรองและคอลัมน์เพิ่มเติมเป็นส่วนที่ออกแบบได้ โดยไม่ถือเป็นฟิลด์บังคับที่ยืนยันแล้ว

### 4.2 สร้างรายการขาย

หน้าจอต้องรองรับข้อมูลต่อไปนี้ โดยลำดับการจัดวางให้ UX/UI ออกแบบให้เหมาะสม:

1. เลือกลูกค้าเดิม หรือเพิ่มลูกค้าใหม่
2. เลือกประเภทบิล: ซื้อสด / ซื้อผ่อน
3. เลือกสินค้าหลายรายการ ระบุจำนวนและราคา พร้อมแสดงยอดรวม
4. เลือกช่องทางชำระเงิน
5. ถ้าซื้อผ่อน ให้กำหนดเงินดาวน์ อัตราดอกเบี้ย จำนวนเดือน และวันครบกำหนดงวดแรก
6. แสดงสรุปก่อนบันทึก รวมค่างวดและตารางผ่อนกรณีซื้อผ่อน
7. บันทึกรายการ และเข้าถึงเอกสาร PDF ที่เกี่ยวข้อง

กรณีซื้อสด: ข้อมูลการขายต้องปรากฏในประวัติลูกค้าที่ A/R

กรณีซื้อผ่อน: ระบบต้องสร้างสัญญาและตารางงวด พร้อมเชื่อมไปแสดงใน A/R

จังหวะที่ถือว่ารายการสมบูรณ์ การมีสถานะร่าง และเงื่อนไขที่อนุญาตให้ออกเอกสารแต่ละประเภท ยังรอกำหนด

### 4.3 บันทึกชำระค่างวด

- พนักงานต้องเข้าถึงลูกค้า สัญญา และงวดที่เกี่ยวข้องก่อนบันทึก
- หน้าจอควรแสดงตารางงวดและยอดคงค้าง เพื่อให้รู้ว่ากำลังบันทึกให้สัญญาใด
- ข้อมูลเสนอสำหรับออกแบบฟอร์ม: วันที่รับชำระ ยอดรับชำระ และงวดที่เกี่ยวข้อง; รายละเอียดฟิลด์และวิธีจัดสรรยอดยังไม่ยืนยัน
- หลังบันทึก ต้องดูรายการที่บันทึกและออกใบเสร็จ PDF ได้
- ประวัติและยอดที่แสดงใน A/R ต้องอัปเดตตามรายการที่บันทึก

## 5. หน้าจอหลักใน A/R

### 5.1 Customer Directory — ทะเบียนลูกค้า

- แสดงรายชื่อลูกค้าทั้งหมด ทั้งซื้อสดและซื้อผ่อน
- รองรับตัวกรองตามสาขา เกรดเครดิต และประวัติประเภทการซื้อสด/ผ่อน ตามขอบเขตที่ร้องขอ
- ลูกค้าคนเดียวอาจมีประวัติซื้อทั้งสองประเภท ตัวกรองจึงต้องไม่บังคับให้ลูกค้าเป็นประเภทใดประเภทหนึ่งถาวร
- เปิด Customer Profile เพื่อดูข้อมูลเชิงลึก
- เกณฑ์เกรดเครดิตและความหมายของสาขาที่ใช้กรองยังรอกำหนด

### 5.2 Customer Profile & Details — โปรไฟล์ลูกค้า

เป็นหน้ารายละเอียดที่เปิดจากทะเบียนลูกค้า ไม่ต้องแยกเป็นเมนูหลัก

| แท็บเสนอ | ข้อมูลที่ต้องรองรับ |
| --- | --- |
| **ข้อมูลส่วนตัว** | ข้อมูลประจำตัวและข้อมูลติดต่อลูกค้า; รายการฟิลด์และฟิลด์บังคับรอกำหนด |
| **ผู้ค้ำประกัน** | ข้อมูลผู้ค้ำและความเกี่ยวข้องกับสัญญา; เงื่อนไขว่าต้องมีผู้ค้ำเมื่อใดยังรอกำหนด |
| **ประวัติการซื้อ** | บิลซื้อสดและซื้อผ่อน รายละเอียดสินค้า ยอดซื้อ และเอกสาร |
| **สัญญาและประวัติการเงิน** | สัญญาผ่อน ตารางงวด Credit History ประวัติรับชำระ และสรุปภาระหนี้ |
| **ประวัติติดตามหนี้** | รายการติดตามหนี้ที่เกี่ยวข้องกับลูกค้า; แหล่งข้อมูลและรายละเอียดรายการรอกำหนด |

ลูกค้าที่ซื้อสดอย่างเดียวต้องดูประวัติซื้อได้ โดยส่วนสัญญา/ภาระหนี้แสดงว่าไม่มีข้อมูลที่เกี่ยวข้อง

### 5.3 รายละเอียดสัญญาและประวัติการเงิน

- แสดงลูกค้า บิลต้นทาง รายการสินค้า และเงื่อนไขผ่อน
- แสดงราคาสินค้าเต็ม เงินดาวน์ อัตราดอกเบี้ย ดอกเบี้ยรวม ยอดที่ต้องผ่อน จำนวนเดือน และค่างวด
- แสดงตารางงวด วันครบกำหนด และสถานะการชำระ
- **Paid vs Overdue Analysis:** แสดงสัดส่วนงวดที่ชำระแล้วเทียบกับงวดเกินกำหนด
- **Recent Transactions:** แสดงรายการชำระเงินล่าสุด พร้อมเปิดรายละเอียดได้
- **Overdue Tracking:** แสดงรายการค้างชำระเกินกำหนด
- **Total Debt Summary:** แสดงยอดภาระหนี้คงค้างและจำนวนงวดที่เหลือ ทั้งระดับสัญญาและสรุปรวมของลูกค้า
- สัญญาที่ชำระครบแล้วยังดูย้อนหลังได้
- **ข้อเสนอเพื่อออกแบบ:** แสดงงวดที่ยังไม่ถึงกำหนดแยกด้วย เพื่อให้ภาพรวมครบ; การจัดกลุ่มงวดที่ชำระบางส่วนและนิยามสถานะยังรอกำหนด
- Credit History ในเอกสารนี้หมายถึงประวัติการผ่อนและชำระ ไม่ได้ยืนยันว่าจะมีระบบคำนวณคะแนนเครดิตอัตโนมัติ

### 5.4 ประวัติรับชำระและรายการเกินกำหนด

- ประวัติรับชำระต้องแยกดูได้ว่าเป็นซื้อสด เงินดาวน์ หรือค่างวด และเชื่อมกลับไปยังลูกค้า/รายการต้นทาง
- รายการเกินกำหนดต้องเปิดดูสัญญา ตารางงวด และประวัติลูกค้าที่เกี่ยวข้องได้
- การสร้างหรือแก้ไขรายการให้กลับไปทำใน Sales โดย A/R คงบทบาทการแสดงข้อมูล
- การดูหรือดาวน์โหลดเอกสารจาก A/R เป็นการเข้าถึงข้อมูล ไม่ใช่การบันทึกรายการใหม่

## 6. Flow สรุปสำหรับออกแบบ

| กรณี | Flow |
| --- | --- |
| **ซื้อสด** | Sales → เลือก/เพิ่มลูกค้า → สร้างบิลซื้อสด → เพิ่มสินค้า → ระบุช่องทางชำระ → บันทึก → ออกเอกสาร → ประวัติปรากฏใน A/R |
| **ซื้อผ่อน** | Sales → เลือก/เพิ่มลูกค้า → สร้างบิลซื้อผ่อน → เพิ่มสินค้า → กำหนดเงื่อนไขผ่อนและช่องทางชำระ → ดูสรุป → บันทึก → ระบบสร้างสัญญา/ตารางงวดใน A/R → ออกเอกสารที่เกี่ยวข้อง |
| **ชำระค่างวด** | Sales → เลือกลูกค้า/สัญญา → บันทึกข้อมูลรับชำระ → ออกใบเสร็จ → A/R อัปเดตประวัติ สถานะงวด และยอดคงค้าง |
| **ดูข้อมูลลูกค้า** | A/R → ทะเบียนลูกค้า → โปรไฟล์ → ประวัติซื้อ/สัญญา/การชำระ/การติดตามหนี้ |

ลำดับช่องข้อมูลใน flow เป็นข้อเสนอให้ UX/UI ปรับได้ ไม่ใช่ข้อบังคับด้านลำดับหน้าจอ

## 7. เรื่องที่รอกำหนด ไม่ต้องสรุป logic แทนในการออกแบบ

| เรื่อง | สิ่งที่ยังไม่ได้ตกลง |
| --- | --- |
| **ข้อมูลลูกค้า/ผู้ค้ำ** | ฟิลด์บังคับ เอกสารแนบ การใช้ข้อมูลผู้ค้ำ และการแก้ไขข้อมูล |
| **วันชำระ** | logic กำหนดวันที่ กรณีวันที่ 29–31 และกรณีพิเศษอื่น |
| **จำนวนเงิน** | ทศนิยม การปัดเศษ การปรับงวดสุดท้าย และขอบเขตค่าที่กรอกได้ |
| **การชำระงวด** | จ่ายบางส่วน จ่ายล่วงหน้า จ่ายหลายงวด ปิดสัญญาก่อนกำหนด และวิธีตัดยอด |
| **หนี้เกินกำหนด** | เกณฑ์นับวัน สถานะ ค่าปรับ และค่าใช้จ่ายเพิ่มเติม |
| **เกรดเครดิต/ติดตามหนี้** | วิธีให้เกรด แหล่งประวัติติดตาม และจุดกรอกข้อมูล |
| **สินค้า/คลัง** | รายละเอียดสินค้าที่ต้องแสดง การเลือกคลัง/สาขา และจังหวะตัดสต็อก |
| **เอกสาร/ภาษี** | รูปแบบ PDF เลขที่เอกสาร ข้อมูลที่ต้องใช้ ส่วนลด การคิด/แสดงภาษี และเอกสารแต่ละจังหวะ |
| **การแก้ไขรายการ** | ยกเลิกบิล คืนสินค้า คืนเงิน แก้ไขการชำระ และแก้ไขสัญญา |
| **สิทธิ์และสาขา** | ใครทำรายการ/ดูข้อมูลใดได้ และขอบเขตการดูข้อมูลข้ามสาขา |
| **สถานะรายการ** | สถานะร่าง/ยืนยัน/ยกเลิก จุดสร้างสัญญา และรายละเอียดสถานะสัญญา/งวด |

การระบุหัวข้อในตารางนี้ไม่ได้หมายความว่าตกลงเพิ่มฟีเจอร์นั้นแล้ว ให้แสดงเป็นประเด็นรอตัดสินใจ และหลีกเลี่ยงการใช้ตัวอย่างใน mockup เป็นกติกาธุรกิจโดยปริยาย
